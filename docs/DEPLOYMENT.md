# Deployment

Atlas Belli is exported by Next.js into `out/`. Production serves static HTML, CSS, JavaScript, JSON, fonts, and PMTiles. No Node process, database, paid map provider, or API key is needed to serve the atlas. The deployed build uses the data artifacts committed under `public/`; downloading and rebuilding source datasets is a separate reproducible operation.

## Build and preview

Use Node 22 or newer (CI and Docker use Node 24), the repository's pnpm version, and the lockfile.

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm lint
NEXT_PUBLIC_SITE_URL=https://your-atlas.example pnpm build
pnpm preview
```

Replace the example origin with the actual public HTTPS origin. It supplies absolute canonical, Open Graph, sitemap, and robots URLs. Without it, local builds deliberately use `http://localhost:3000`; do not publish that development origin. `NEXT_PUBLIC_SITE_URL` is public configuration, not a secret. Nothing else is required in an environment file.

The build prerenders the methodology, each war catalog entry, and important event pages (importance at least 60, editorial selection, or war/campaign/treaty types). These routes read generated local JSON during the build. Historical values are formatted by `histdate`; no `Date` parsing is used for historical years. A static PNG Open Graph image is generated by Next.js; no image server is needed.

The preview server uses port 3000. Stop an existing development server before auditing production so that tests cannot accidentally inspect development assets. Browser tests can target a running deployment with `PLAYWRIGHT_BASE_URL=https://your-atlas.example pnpm test:e2e`.

## Vercel production

The public project is linked to [ZakiChair/atlas-belli](https://github.com/ZakiChair/atlas-belli), with `main` as its production branch and [atlas-belli.vercel.app](https://atlas-belli.vercel.app) as its production domain. Vercel uses the Next.js preset and Node 24; the application retains its static export.

`NEXT_PUBLIC_SITE_URL=https://atlas-belli.vercel.app` is configured for Production and Preview so canonical, sitemap and Open Graph URLs refer to the public site. The value is public configuration. Local Vercel credentials and `.env` files are excluded from Git and CLI uploads.

`vercel.json` supplies the MIME types needed by PMTiles, MapLibre module workers and the generated Open Graph image. PMTiles use browser revalidation because their paths are stable between data publications. Versioned MapLibre modules can be cached immutably. The Vercel CDN supplies byte ranges and compression; the Nginx configuration is specific to Docker.

Pushes to `main` trigger production deployments through the Git integration. For a manual deployment from an authenticated, linked checkout:

```sh
vercel deploy --prod --archive=tgz
```

The split archive upload is important for this repository's source-file count. `.vercelignore` excludes acquisition caches, local exports, credentials and test artifacts. The committed data artifacts are included and the remote build does not rerun Wikidata acquisition.

## Docker on a VPS

```sh
docker build --build-arg NEXT_PUBLIC_SITE_URL=https://your-atlas.example -t atlas-belli:local .
docker run --rm --name atlas-belli -p 8080:8080 atlas-belli:local
```

The image uses a Node build stage and a Nginx runtime stage, serves port 8080 as the `nginx` user, and has a health check. Point the VPS's existing HTTPS reverse proxy at that port. Configure certificates and the real hostname in that reverse proxy. The repository does not deploy or publish automatically.

For a persistent container:

```sh
docker run -d --restart unless-stopped --name atlas-belli -p 127.0.0.1:8080:8080 atlas-belli:local
```

The Nginx configuration is a full `nginx.conf`; it provides correct static 404 behavior, byte ranges, gzip level 6 for text assets, immutable caching for hashed Next.js assets, and revalidation for mutable data manifests. PMTiles are not re-compressed. Deploy HTML and data together as one immutable build/image; changing a manifest in place while keeping old tiles can create inconsistent views.

## PMTiles hosting contract

The browser must receive HTTP byte ranges (`206 Partial Content`) when requesting tile archive slices. Do not put `.pmtiles` behind middleware that returns HTML, ignores Range, or adds gzip content encoding. A basic check against the deployed site:

```sh
curl -i -H 'Range: bytes=0-126' https://your-atlas.example/geo/natural-earth.pmtiles
```

Expected: status 206, a `Content-Range` header, a 127-byte body beginning with `PMTiles`, and no `Content-Encoding: gzip`. `nginx.conf` supports this without a tile server. Static JSON files use `Cache-Control: no-cache` so manifests and entity details revalidate. The PMTiles URL paths are stable across rebuilds, so their caching period is bounded rather than marked immutable.

Same-origin hosting needs no CORS configuration. If moving PMTiles to another static origin, allow the atlas origin, permit Range requests, and expose `Content-Range`, `Content-Length`, `Accept-Ranges`, and `ETag` response headers. Keep the source archives and licence files publicly available.

## Rebuild the data

Rebuilding requires Python 3.11+ and tippecanoe 2.17+ in the data-building environment. The runtime image does not need them.

```sh
pnpm data:build
pnpm build
```

The pipeline acquires pinned geography and Wikidata sources with caching, normalizes records, scores, validates, deduplicates, and writes optimized artifacts and reports. Wikidata acquisition is polite and can take substantially longer than an application build. Inspect `public/data/quality.json` and the reports under `data/reports/` before accepting a new dataset. Cache files remain under `data/raw/` and are not committed. An interruption can be resumed by rerunning the command.

Use `pnpm data:build --offline` only when the raw acquisition cache already exists. It rebuilds the events from cached evidence without network acquisition; it does not reconstruct missing geography. Use `pnpm data:geo` to rebuild all geography independently. See [DATA.md](DATA.md) and [GEOGRAPHY.md](GEOGRAPHY.md) for schemas, source versions, anomalies, and licences.

Do not change the frozen geography revision without reviewing its licence, updating source locks deliberately, rebuilding PMTiles, and reviewing date conventions. A changed payload behind a pinned URL fails SHA verification.

## Verification and budgets

```sh
pnpm check
python3 -m unittest discover -s pipeline/geography -p 'test_*.py'
pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
pnpm test:performance
pnpm audit:lighthouse
```

Playwright tests the static preview in Chromium desktop and mobile contexts. Linux CI installs browser system dependencies as well. Browser accessibility checks are part of the E2E suite. The separate hardware Lighthouse audit uses mobile DevTools throttling, runs three measurements per target and fails if the median Performance is below 85, Accessibility below 95, or SEO below 95. Reports are local files under `.lighthouseci/` and uploaded as workflow artifacts; they are not published to an external report service.

The acceptance targets also include a 300 KB gzip initial JavaScript budget and interactive frame-rate requirements. Lighthouse category thresholds alone do not certify those two conditions: inspect bundle loading and measure the actual WebGL experience on representative hardware. Software-rendered CI Chromium is useful for regression testing but cannot certify laptop GPU frame rate. This documentation does not claim unmeasured scores.

## External requests in use

The basemap, boundaries, event archives, search indexes and fonts are hosted with the site. Opening event details may request Wikipedia summaries and Wikimedia images; their availability is independent of the local data archive. The interface retains source links and event facts when the summary service is unavailable. No secret keys or proprietary map tokens are involved.

## Graphics workers and hardware audits

`pnpm dev` and `pnpm build` prepare the installed MapLibre module worker and its shared module under a versioned `/vendor/maplibre/` path. Those generated copies are ignored by Git. Their licence is copied alongside them. Nginx explicitly serves `.mjs` as JavaScript; do not replace this with an HTML fallback. This is required by MapLibre 6 after bundling its main module with Next.js.

`pnpm test:e2e` is the portable functional suite. `pnpm test:performance` is a separate frame-budget suite; it uses the native GPU by default, runs serially and retains the 30 fps threshold. `pnpm audit:lighthouse` locates the installed Playwright Chromium, runs the three mobile audits with native graphics, and enforces the unchanged 85/95/95 thresholds. Set `PLAYWRIGHT_GPU=software` deliberately to compare SwiftShader; that comparison is expected to differ substantially and is recorded separately.

GitHub's cloud job runs functional and accessibility checks. The workflow's `gpu_audit` dispatch input starts the additional hardware-budget job on a self-hosted runner labelled `atlas-gpu`. Register such a runner with an operational graphics driver before requesting that job. A skipped hardware job is not a performance certification; the local measured results and hardware are documented in `docs/QA.md`.

For byte and time measurements, run `pnpm measure:bundle` after building, then `pnpm measure:runtime` against the running preview. `pnpm measure:runtime -- --slow-4g` records the full map startup using request-level network and CPU throttling. The shell budget and the complete interactive-map payload are separate figures.
